### Finding 5 — Brand API: docs inconsistently describe the SVG import strategy

| Field | Value |
|---|---|
| **File** | `README.md:29`, `CHANGELOG.md` 0.5.0 entry, `docs/brand.md:17` |
| **Current fact** | The source code uses **two** different strategies: `<MagiMark>` uses Vite `?url` + `<use href={markUrl}>` (a 1:1 mark without text glyphs); `<MagiWordmark>` / `<MagiLockup>` use `?raw` + `dangerouslySetInnerHTML` (they embed `<text>` glyphs with the page font and need inline injection to render the font). |
| **Documented claim** | Some docs said `?raw` import for all brand components. |
| **Source of truth** | `src/brand/MagiMark.tsx` (uses `?url`), `src/brand/MagiWordmark.tsx` and `src/brand/MagiLockup.tsx` (use `?raw`). |
| **Fix** | Update docs to reflect the actual mixed strategy and explain why (`<text>` glyph needs page font). |
| **Breaking change** | No. Documentation-only; no source-code change. |

- **CI workflow** — `.github/workflows/ci.yml` runs `check-tokens.mjs`, `check-accent-tokens.mjs`, `npm run build`, `npm run typecheck` on every push/PR. The script paths and inputs match the actual scripts in `scripts/`.
- **CI script target** — `scripts/check-accent-tokens.mjs` reads `tokens/accent-presets.ts` (since 0.5.1). Verified in this audit. No drift.
